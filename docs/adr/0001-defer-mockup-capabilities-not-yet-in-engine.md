# Defer several Clocktower Storyteller mockup capabilities for the v1 chassis port

We're porting the `Clocktower Storyteller.dc.html` design (the `2a`/`3a` "Night console" chassis, extended through `4a`-`4d`) into the Leptos app across all five game phases. The mockup depicts several capabilities the engine doesn't have: a "why" reasoning trace for auto-resolved outcomes, an inline override widget for auto-computed reveals (letting the storyteller fudge an answer before "showing the player"), setup-time bag/role-conflict warnings (e.g. dealing the Baron when there aren't enough Outsiders left), and non-linear step navigation (clickable jump-to-step in the rail, "jump back to that step" from the log).

We're deferring all four for this pass, tracked as follow-ups in `TODO.md`. Manual mode is being built as the generic state-tree editor already planned in `TODO.md` (replacing the whole content area) rather than the mockup's inline per-seat edit panel — it already covers ad hoc overrides, including the "give false info" case, since this app is storyteller-only and nothing is ever shown directly to a player from this screen. The rail step list and log stay linear: clicking a past step shows a read-only view of what happened there, it does not rewind, since real jump/rewind navigation is the same underlying problem as the already-tracked, unbuilt Undo/replay feature and shouldn't be solved twice.

The mockup's full-screen log modal also has `MANUAL ONLY` and `FALSE INFO` filters, which assume every log entry is tagged with its source (auto vs. manual) and, for info reveals, its truthfulness. Neither tag exists on `Event` today, and Manual mode isn't writing to the log at all this pass (see `CONTEXT.md`), so both filters are deferred. The `DEATHS` filter is kept — it can filter on existing `Event::Death`/`Event::Execution` variants with no engine change.

Each of these is a nontrivial engine feature in its own right, not a property of the UI chassis. Scoping them out keeps this pass to "port the chassis + build the generic state editor" instead of quietly growing into several separate feature builds. Consequence: the delivered UI won't visually match the mockup 1:1 in these spots — no WHY trace, no override buttons, no setup warnings, no jump navigation, no manual/false-info log filters. That's intentional.
