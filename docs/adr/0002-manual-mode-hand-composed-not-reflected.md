# Manual mode: hand-composed field editors, not generic reflection

`TODO.md`'s Manual mode spec ("user should be able to access every property of the game state and change them," collapsible structs/vectors, bool toggles, validated inputs, alignment-colored enum dropdowns) reads like it wants a generic, reflection-based editor: walk the whole state tree at runtime, render each field by its type. Rust has no runtime reflection, and `State`/`Player` don't derive `Serialize`/`Deserialize` — `Player.role` is a `Box<dyn Role>` trait object (the enum-dispatch role system), which resists automatic serialization. Building true reflection would mean adding serialization across the whole state graph first, which overlaps with the separate, already-tracked "Saving the game state" TODO item.

Decision: build Manual mode as a hand-composed structural mirror instead. Write a small set of reusable, typed field-editor components (bool toggle, validated number input, alignment-colored enum dropdown, collapsible struct/vector wrapper) and explicitly compose them to match `State`'s actual known shape, using the `reactive_stores::Store` derive `State`/`Player` already have for fine-grained reactive field access. This isn't generic reflection — the tree is written by hand once — but each field-editor component is reused everywhere that value type appears, so it delivers the same end-user experience `TODO.md` describes.

Consequence: adding a new field to `State`/`Player` requires manually wiring it into the Manual-mode view, not just deriving a trait. If the state graph ever gains full `Serialize`/`Deserialize` support (e.g. for save/load), reflection-based (A) becomes viable and could replace this — but that's a separate, larger change, not assumed here.
